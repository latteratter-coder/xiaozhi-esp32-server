意图识别与工具调用链

xiaozhi-server · function_call 模式下的意图预检与工具分发 · 基于源码分析生成

ActionResponse 四种动作类型

RESPONSE
工具直接返回结果文本 → speak_txt() 送TTS播放
REQLLM
工具结果需要LLM二次加工 → 结果写入dialogue → 调用LLM生成回复 → TTS
ERROR / NOTFOUND
工具调用失败/未找到 → 播报错误提示文本
NONE
无操作（多工具调用合并时无有效响应）

流程说明

1
ASR 识别结果通过 startToChat() 进入，调用 handle_user_intent(conn, text)
2
JSON 预处理：若文本含 speaker/content 字段，提取实际内容和说话人信息
3
check_direct_exit()：匹配退出指令列表（cmd_exit），匹配成功则直接关闭连接
4
checkWakeupWords()：匹配唤醒词缓存，命中则播放预缓存音频回复（2秒内忽略VAD）
5a
function_call 模式: 预检全部未命中 → return False，交由 chat() 中的 LLM 自行决定是否调用工具
5b
intent_llm 模式: 调用 intent.detect_intent() 进行独立的 LLM 意图分析，返回 JSON 格式的 function_call
6
LLM 流式响应解析：direct_answer 虚拟工具的 response 参数实时送 TTS；真实工具调用收集到 tool_calls_list
7a
direct_answer → 文本已流式播报完毕，写入对话历史，发送 LAST 信号结束
7b
real_tool_calls → 上报工具调用 → UnifiedToolHandler.handle_llm_function_call()
8
ToolManager.execute_tool() 按工具名查找 ToolType，分发到 5 类执行器之一
9
执行器返回 ActionResponse，包含 action 类型 + result + response 文本
10
根据 action 类型处理结果：RESPONSE→直接TTS播报 / REQLLM→结果回传LLM递归chat / ERROR→播报错误提示
