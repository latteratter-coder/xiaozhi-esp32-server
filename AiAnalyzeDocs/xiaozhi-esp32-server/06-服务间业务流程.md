## 3. 核心业务流程详解

### 3.1 设备首次上电 → 激活绑定 → 语音对话

> **重要说明**：设备绑定状态校验涉及**两个阶段**和**两道关卡**，OTA 阶段始终返回真实的 WebSocket 地址，绑定状态的实际校验发生在 WebSocket 连接建立之后。

#### 3.1.1.1 关键点：绑定提示的"双端播报"机制

未绑定设备的绑定提示由**设备端**和**服务端**分别播报一次，互为补充：

| 时机 | 播报端 | 触发源 | 内容 |
|------|--------|--------|------|
| 设备开机后，OTA 响应返回 `activation.code` 时 | **设备端本地** | `application.cc::ShowActivationCode()` 解析 `activation.code` | 屏幕显示激活提示文本 + 播放 `OGG_ACTIVATION` + 逐位播放 `OGG_0..OGG_9` 数字音 |
| WebSocket 连接建立后，用户第一次说话时 | **xiaozhi-server 通过 WS 下发** | `receiveAudioHandle.py::check_bind_device()` 根据 `need_bind=True + bind_code` | STT 文本 "请登录控制面板，输入 123456，绑定设备" + `bind_code.wav` + 6 个数字音 |

这种互补设计保证了：
- 即使设备尚未建立 WebSocket（比如一直在轮询 `/ota/activate` 等待用户输入），设备本地也能播报激活码
- 即使设备本地没有 OGG 资源文件（极端情况），服务端也能通过 WS 下发音频补播

> **运行验证**：设备端播报由 `main/ota.cc` + `main/application.cc` 源码确认；服务端播报由 Docker 容器 + Mock manager-api 的 3 种绑定场景测试全部通过（场景一/二/三均符合预期），详见 **17-设备启动流程运行验证报告.md** §5（绑定设备流程验证）、§7.3（全模块部署完整时序）。

#### 3.1.2 两道关卡机制详解

```
设备启动
  ↓
POST /ota/ (manager-api Java端)
  ├── 返回 WebSocket URL（始终真实，不管设备是否绑定）
  ├── 返回 auth token（如果 auth_enabled=true，与绑定无关）
  └── 返回 firmware 信息
  │     ├── 未绑定设备 → version=当前版本(回显) + url=INVALID_FIRMWARE_URL(占位)
  │     │   设备 IsNewVersionAvailable() 版本比对判定无更新 → 跳过 Upgrade()
  │     │   同时返回 activation 激活码
  │     └── 已绑定设备 → 真实固件升级URL（如果有新版本）
  ↓
设备建立 WebSocket 连接到 xiaozhi-server
  ↓
[第一道关卡] WebSocket JWT 认证（默认关闭，auth_enable=false）
  源码: websocket_server.py → _handle_auth()
  ├── 开启且token无效 → 发送"认证失败" → 断开连接（不播报绑定提示）
  └── 关闭 或 token有效 → 继续
  ↓
后台异步初始化: _initialize_private_config_async()
  源码: connection.py → 向 manager-api 请求设备私有配置
  ├── 设备已绑定Agent → 正常返回配置 → need_bind=False → 初始化全部组件
  ├── 设备未注册 → DeviceNotFoundException → need_bind=True（无bind_code）
  └── 设备注册但未绑定Agent → DeviceBindException(含绑定码) → need_bind=True + bind_code
  ↓
[第二道关卡] 设备绑定检查（用户说话时触发，非连接时）
  源码: connection.py → _route_message() + receiveAudioHandle.py → startToChat()
  ├── need_bind=True + 有bind_code → 播报"请输入XXXXXX绑定设备"（逐位播报数字）
  ├── need_bind=True + 无bind_code → 播报"未找到版本信息，请配置OTA地址"
  └── need_bind=False → 正常进入语音对话流程
```

## 4. 认证机制汇总

### 4.1 三种认证场景

```
┌─────────────────────────────────────────────────────────┐
│                    认证场景                              │
├──────────────┬──────────────────┬───────────────────────┤
│ 用户认证     │ 服务间认证        │ 设备认证              │
│ (oauth2)     │ (server secret)  │ (HMAC JWT)            │
├──────────────┼──────────────────┼───────────────────────┤
│ Bearer:      │ Bearer:          │ Bearer:               │
│ SysUserToken │ server.secret    │ HMAC-SHA256签名.时间戳 │
│ (UUID)       │ (系统参数)        │                       │
├──────────────┼──────────────────┼───────────────────────┤
│ 适用:        │ 适用:            │ 适用:                  │
│ 前端→Java    │ Python→Java      │ 设备→Python WebSocket  │
│              │ Java→Python      │ Vision API             │
├──────────────┼──────────────────┼───────────────────────┤
│ 校验方:      │ 校验方:          │ 校验方:                │
│ Oauth2Realm  │ ServerSecret     │ AuthManager            │
│ (DB查Token)  │ Filter           │ (HMAC验签+时间窗)      │
│              │ (字符串比对)      │                        │
└──────────────┴──────────────────┴───────────────────────┘
```

### 4.2 密钥统一

```
app.py 启动时确定 auth_key:
  server.auth_key → manager-api.secret → 随机UUID

该 auth_key 统一用于:
├── WebSocket 设备连接 HMAC 签名
├── OTA 返回的 WebSocket token
├── Vision API 的 JWT 签名
└── 与 manager-api 的 server.secret 保持一致
```
