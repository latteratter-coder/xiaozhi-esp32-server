完整流程说明

1
客户端持续发送 opus 编码音频帧（每帧 60ms），通过 WebSocket 到达 _route_message()
2
音频 bytes 放入 asr_audio_queue（线程安全队列），由 asr_text_priority_thread 独立线程消费
3
每帧音频经过 Silero VAD (ONNX) 模型推理，输出语音概率 speech_prob，采用双阈值判断（高阈值 0.5 确认有声音，低阈值 0.2 确认静音）
4a
检测到人声 → 音频追加到 asr_audio 缓冲区，更新滑动窗口（连续 3 帧有声确认为有效语音）
4b
静默时间超过阈值（默认 1000ms）→ 标记 client_voice_stop=True，触发语音结束
5
handle_voice_stop() 被调用，准备进行 ASR 识别（非流式模式下使用缓冲区全部音频）
6
asyncio.gather() 并行执行两个任务：ASR speech_to_text() 语音识别 + 声纹 identify_speaker() 说话人识别
7
识别结果传入 startToChat(conn, text)，进行前置检查：绑定状态 → 输出限制 → 打断当前播放
!
need_bind=True → 播报绑定提示音后返回
!
超出日输出限制 → 播报告别语后返回
!
设备正在说话（非 manual 模式）→ handleAbortMessage() 打断播放
8
handle_user_intent() 进行意图预检查：退出指令 → 唤醒词 → function_call 意图识别。若意图已处理则不再进入 LLM 对话
9
send_stt_message() 将用户文本通过 WebSocket 发送给客户端显示，同时发送 TTS start 信号
10
通过 executor.submit(conn.chat) 将 LLM 对话放入线程池异步执行，不阻塞主事件循环
11
chat() 方法：组装对话历史 + 记忆 → 调用 llm.response_with_functions() 获取流式 SSE 响应
12
LLM 流式响应逐 chunk 解析：direct_answer 直接回复内容实时入 TTS 队列；工具调用则执行后递归 chat
13
文本按句分段（_get_segment_text），逐段送入 TTS 流式合成引擎（如火山/阿里/讯飞）
14
合成后的 opus 音频帧进入 tts_audio_queue，由播放优先级线程按 60ms 间隔消费
15
sendAudioMessage() 通过 WebSocket 将音频帧发送给客户端播放，支持流控和预缓冲
