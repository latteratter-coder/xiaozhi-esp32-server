# 本地编译部署与测试操作指南

## 一、部署目录说明

- 全模块部署使用 `main/xiaozhi-server/docker-compose_all.yml`，包含 Server、Web（智控台）、MySQL、Redis 四个容器
- 用户自定义配置放在 `main/xiaozhi-server/data/.config.yaml`
- `docker-compose.override.yml` 用于覆盖默认配置（如模型挂载、端口映射等），无需修改主 compose 文件

---

## 二、Docker 容器管理

### 2.1 常用命令

```bash
# 查看所有容器
docker ps -a --filter "name=xiaozhi"

# 启动全模块服务
cd main/xiaozhi-server
docker compose -f docker-compose_all.yml -f docker-compose.override.yml up -d

# 停止全模块服务
docker compose -f docker-compose_all.yml -f docker-compose.override.yml down

# 重启 server 容器（修改配置后）
docker restart xiaozhi-esp32-server

# 查看实时日志
docker logs -f xiaozhi-esp32-server
```

### 2.2 容器列表

| 容器名 | 镜像 | 宿主机端口 → 容器端口 | 说明 |
|--------|------|----------------------|------|
| xiaozhi-esp32-server | ghcr.nju.edu.cn/xinnan-tech/xiaozhi-esp32-server:server_latest | 18000→8000, 18003→8003 | Python 核心服务 |
| xiaozhi-esp32-server-web | ghcr.nju.edu.cn/xinnan-tech/xiaozhi-esp32-server:web_latest | 18002→8002 | Java API + Vue 前端（智控台） |
| xiaozhi-esp32-server-db | mysql:latest | 内部 3306 | MySQL 数据库 |
| xiaozhi-esp32-server-redis | redis:8.0 | 内部 6379 | Redis 缓存 |

> **端口说明**：WSL2 环境下 Windows 的 IP Helper 服务（`iphlpsvc`）会顽固占用 8000/8002/8003 等常用端口，因此宿主机端口映射为 18000/18002/18003。详见第七节。

## 三、本地编译与 Docker 镜像打包

### 3.1 构建 Server 镜像（Python 后端）

两层 Dockerfile：
- `Dockerfile-server-base`：基础镜像（系统依赖 + Python 包，构建慢）
- `Dockerfile-server`：生产镜像（仅应用代码，基于 base，构建快）

```bash
cd /home/one/xiaozhi-esp32-server
# 第一步：构建基础镜像
docker build -f Dockerfile-server-base -t xiaozhi-server:base .
# 第二步：构建生产镜像
docker build -f Dockerfile-server -t xiaozhi-server:local .
```

### 3.2 构建 Web 镜像（Vue前端 + Java后端）

使用 `Dockerfile-web`（多阶段构建：Node构建Vue + Maven打包Java + Nginx+JRE运行）：

```bash
docker build -f Dockerfile-web -t xiaozhi-web:local .
```

### 3.3 导出/导入镜像

```bash
# 导出
docker save xiaozhi-server:local -o xiaozhi-server-local.tar
docker save xiaozhi-web:local -o xiaozhi-web-local.tar

# 导入
docker load -i xiaozhi-server-local.tar
docker load -i xiaozhi-web-local.tar
```

> **注意**：全模块部署默认使用预构建镜像（`ghcr.nju.edu.cn/xinnan-tech/xiaozhi-esp32-server:server_latest` / `:web_latest`），无需本地构建。本地构建仅在需要自定义代码时使用。

## 七、WSL2 端口冲突问题

### 7.1 问题现象

WSL2 环境下，Docker 绑定端口 8000/8002/8003 时报错 `address already in use`，但 Linux 侧用 `ss -tlnp` 查不到任何进程占用。

### 7.2 根因

Windows 的 **IP Helper 服务（`iphlpsvc`，svchost 子进程）** 在 Windows 侧的 `127.0.0.1` 上监听了这些端口，用于 IPv6 过渡技术（ISATAP/6to4/Teredo/IP-HTTPS）。该端口绑定在 Windows 网络栈层面，WSL 的 Linux 侧完全不可见，但 Docker 通过 WinNAT 映射端口时会与之冲突。

验证方法（在 Windows PowerShell 中执行）：
```powershell
Get-NetTCPConnection -LocalPort 8000,8002,8003 | Format-Table LocalAddress,LocalPort,State,OwningProcess
Get-WmiObject Win32_Service | Where-Object {$_.ProcessId -eq <PID>}
```

### 7.3 解决方案

将 Docker 宿主机端口映射为高位端口（在 `docker-compose_all.yml` 中修改）：

| 容器内端口 | 宿主机端口 | 服务 |
|-----------|-----------|------|
| 8000 | **18000** | WebSocket |
| 8002 | **18002** | 智控台 |
| 8003 | **18003** | HTTP/OTA |

## 八、Docker DNS 配置注意事项

### 8.1 问题

在 `daemon.json` 中添加 `"dns": ["8.8.8.8", "114.114.114.114"]` 会导致 Docker 内嵌 DNS（`127.0.0.11`）被覆盖，容器间无法通过主机名互相解析（如 web 容器无法解析 `xiaozhi-esp32-server-db`）。

### 8.2 解决

**不要**在 `/etc/docker/daemon.json` 中设置 `dns` 字段。WSL2 下 Docker 默认使用宿主机 DNS（`192.168.1.1`）即可正常工作。

```json
{
  "registry-mirrors": [
    "https://docker.1panel.live",
    "https://hub.rat.dev"
  ]
}
```

## 十、数字人模块

### 10.1 简介

数字人（`main/digital-human/`）是独立的本地测试模块，提供浏览器交互页面，通过 WebSocket 连接后端 Server 进行对话测试。

### 10.2 启动

```bash
cd /home/one/xiaozhi-esp32-server/main/digital-human
pip3 install -r wakeword_runtime/requirements.txt
python3 start.py
```

启动后访问 `http://127.0.0.1:18006/index.html`，OTA 地址填写 `http://127.0.0.1:18003/xiaozhi/ota/`，点击"拨号"即可连接后端。

### 10.3 端口说明

默认端口 8006 同样可能被 IP Helper 占用，需修改为 18006：
- 修改文件：`main/digital-human/wakeword_runtime/runtime/http_server.py`
- 将 `port: int = 8006` 改为 `port: int = 18006`

## 十一、性能测试

项目自带端到端性能测试脚本：`deploy/perf_test.py`

```bash
python3 deploy/perf_test.py
```

测试项包括：OTA 接口延迟、WebSocket 握手延迟、LLM+TTS 全链路对话延迟（TTFT）。

实测结果参考（glm-4-flash + EdgeTTS）：
- OTA 接口：~1.4ms
- WS 握手（含 hello）：~10ms
- TTFT（首句响应）：~3.2s（中位数 2.8s）

## 十三、常见问题排查

| 问题 | 排查方法 |
|------|----------|
| 端口绑定失败 `address already in use` | Windows PowerShell 执行 `Get-NetTCPConnection -LocalPort 8000` 检查 IP Helper 占用，改用高位端口 |
| 容器间 DNS 解析失败 | 检查 `daemon.json` 是否包含 `dns` 字段，移除后重启 Docker |
| ASR 模型下载失败 | 容器内无法联网，通过 `docker-compose.override.yml` 挂载本地模型 |
| WebSocket 连接被立即关闭 | 检查是否发送了 `hello` 握手消息 |
| LLM 调用失败 | 检查 `data/.config.yaml` 中的 API Key 是否有效 |
| 智控台无法连接数据库 | 等待 MySQL 健康检查通过（`healthy`），检查容器是否在同一 Docker 网络中 |
| 天气查询失败 | `curl` 测试天气 API 是否可达 |
| OTA 返回的 WebSocket 地址是 Docker 内部 IP | 在 `.config.yaml` 中显式设置 `server.websocket` 为宿主机地址 |
