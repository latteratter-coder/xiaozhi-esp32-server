完整流程说明

1
ESP32 设备启动，向 xiaozhi-server 的 HTTP 端口(8003) 发送 POST /xiaozhi/ota/ 请求
2
xiaozhi-server 的 OTAHandler 解析设备型号/版本，通过 AuthManager.generate_token() 生成 HMAC token，构建 WebSocket URL，扫描 data/bin/ 检查固件更新
3
设备携带 device-id、client-id、authorization headers 发起 WebSocket 连接
4
WebSocketServer._handle_auth() 执行 HMAC-SHA256 token 校验
5a
认证通过 → 创建 ConnectionHandler 处理该连接
5b
认证失败 → 发送"认证失败"消息并断开连接
6
通过 asyncio.create_task() 启动后台初始化，主循环同步开始接收消息（零阻塞）
7
后台调用 ManageApiClient → POST /config/agent-models 查询设备绑定状态和私有配置
8a
API 返回 code=0 → 设备已绑定，need_bind=False，正常初始化所有组件
8b
API 返回 code=10041 → 设备未找到，need_bind=True
8c
API 返回 code=10042 → 需要绑定码，need_bind=True + 生成6位 bind_code
9
消息路由: 绑定通过则正常处理（Text→handleTextMessage / Bytes→ASR队列）；未绑定则丢弃消息并播报绑定提示音

认证三元组: HMAC-SHA256

Token 生成: _sign(client_id | device_id | timestamp) → signature.timestamp

Token 不含明文身份信息，仅携带签名+时间戳。服务端使用相同的 secret_key 重新计算签名并比对。

有效期默认 30天（2,592,000秒），过期后 token 失效。

白名单设备 配置在 auth.allowed_devices 中，直接放行不做 token 校验。

流程说明

1
ESP32 设备发起 WebSocket Connect 请求
2
服务端从请求 Headers 中提取 device-id、client-id、authorization 三元组
3
将三元组传入 AuthManager.verify_token() 进行认证
4a
若设备在 allowed_devices 白名单中 → 跳过校验，直接放行
4b
不在白名单 → 进入 HMAC 签名验证
5
拆分 token: token.split(".") → 得到签名部分 sig 和时间戳 ts
6
检查过期: time.now() - ts < expire_seconds（默认30天）
7
使用服务端 secret_key 重新计算 _sign(client_id|device_id|ts)，与 sig 比对
8a
签名匹配 → 认证通过，继续创建 ConnectionHandler
8b
过期或不匹配 → 抛出 AuthenticationError，连接断开

绑定校验的关键设计

延迟校验策略: OTA 阶段不校验绑定状态，始终返回真实 WebSocket 地址。绑定校验推迟到 WebSocket 连接建立后异步获取设备配置时进行。

事件机制: bind_completed_event (asyncio.Event) 作为信号量，主循环每条消息进入时等待最多 1 秒。

绑定提示: 当 need_bind=True 且有 bind_code 时，设备播报"请输入6位绑定码"；无绑定码时播报"未找到设备版本信息"。

间隔控制 绑定提示每 60秒 最多播报一次，防止频繁骚扰。

流程说明

1
WS 连接建立后，主循环立即开始接收消息；同时通过 asyncio.create_task 启动后台初始化
2
后台调用 ManageApiClient → POST /config/agent-models 获取设备私有配置
3a
API 返回 code=0 → 设备已绑定到 Agent
3b
code=10041 → DeviceNotFoundException，设备未在系统中注册
3c
code=10042 → DeviceBindException，设备已注册但未绑定，携带6位绑定码
4
根据 API 结果设置 need_bind 标志，并调用 bind_completed_event.set() 通知主循环
5
主循环中每条消息进入 _route_message() 时，首先检查绑定状态
6
等待 bind_completed_event，最多 1 秒超时
7a
超时未收到结果 → 丢弃当前消息（等待后台初始化完成）
7b
已收到结果 → 继续检查 need_bind 标志
8a
need_bind=True → 丢弃消息 + 播报绑定提示音（每60秒一次）
8b
need_bind=False → 正常路由消息到 Text/Audio 处理链路

非阻塞设计要点

主循环零延迟: handle_connection() 中通过 asyncio.create_task() 将初始化放入后台，主循环立即开始 async for message in websocket 接收消息。

两步初始化: Step 1 异步获取远程配置（IO密集型），Step 2 在线程池中初始化组件（CPU密集型），避免阻塞事件循环。

绑定短路: 当 need_bind=True 时，_initialize_components() 仅初始化 DefaultTTS（用于播报绑定提示），跳过 ASR/LLM/Memory 等重型组件，节省资源。

并发优化 asyncio.gather() 并行调用 get_agent_models 和 get_correct_words，减少 API 等待时间。

流程说明

1
