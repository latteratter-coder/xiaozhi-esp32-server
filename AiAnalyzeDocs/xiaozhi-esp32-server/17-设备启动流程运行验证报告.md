## 2. 流程一：设备启动（OTA → WebSocket 连接 → 认证）

### 2.1 流程时序图

```mermaid
sequenceDiagram

    participant Device as ESP32 设备

    Device->>OTA: GET /xiaozhi/ota/ (健康检查)
```

## 3. 流程二：语音对话（listen → LLM → TTS → 音频输出）

### 3.1 流程时序图

```mermaid
sequenceDiagram
    autonumber
    participant Device as ESP32 设备
    participant WS as WebSocket
    participant Route as _route_message
    participant Listen as ListenHandler
    participant Chat as chat()
    participant LLM as ChatGLM<br/>glm-4-flash
    participant TTS as EdgeTTS

    Device->>WS: {"type":"listen","state":"detect","text":"你好"}

    WS->>Route: _route_message(str)
    Note over Route: bind_completed_event ✅<br/>need_bind=False → 放行

    Route->>Listen: handleTextMessage()
    Note over Listen: ListenTextMessageHandler<br/>state=detect → startToChat()

    Listen->>Chat: executor.submit(conn.chat, "你好")
    Note over Chat: send_stt_message("你好")

    Chat->>LLM: response_with_functions(dialogue, functions)
    LLM-->>Chat: 流式返回 "嗨，我在呢，咋回事呀？"
    Note over Chat: 表情提取: 🙂<br/>文本逐句送TTS队列

    Chat->>TTS: tts_text_queue: "嗨"
    TTS-->>Device: Opus 音频帧 ×18

    Chat->>TTS: tts_text_queue: "我在呢，咋回事呀？"
    TTS-->>Device: Opus 音频帧 ×28

    Chat->>TTS: SentenceType.LAST
    TTS-->>Device: {"type":"tts","state":"stop"}
```

### 3.2 实测验证

**§6.2 startToChat 流程验证（7 项）**：

| # | 文档描述 | 验证条件 | 实际结果 | 结果 |
|---|---------|---------|---------|:----:|
| 1 | 解析JSON格式(含speaker/language/content) | listen detect 文本直接传入 | 非JSON文本跳过解析，继续执行 | ✅ |
| 2 | 绑定检查 → check_bind_device() | need_bind=False 通过 | STT/TTS 正常返回，未触发绑定播报 | ✅ |
| 3 | 输出字数限额 → max_out_size() | 未触发限额 | 正常对话，无限制提示 | ✅ |
| 4 | handleAbortMessage (非manual且客户端在播时) | 首次对话无需打断 | client_is_speaking=false，无 abort | ✅ |
| 5 | handle_user_intent(text) | intent_type=function_call → 返回False | 跳过意图分析进入 chat | ✅ |
| 6 | send_stt_message() | STT 文本回显到客户端 | 收到 type=stt, text=你好 | ✅ |

### 5.1 新设备首次开机时序

```mermaid
sequenceDiagram

    JavaAPI->>JavaAPI: buildActivation()<br/>生成6位随机激活码
    JavaAPI->>Redis: SET ota:device:{safeMac} → {activation_code, ...}
    JavaAPI->>Redis: SET ota:activation:{code} → deviceId
    JavaAPI-->>Device: {activation:{code:"847291", message},<br/>firmware:{version:"当前版本",url:INVALID},<br/>websocket:{url,token}}

    Note over Device: firmware.version == 上报版本<br/>IsNewVersionAvailable()=false<br/>跳过Upgrade()<br/>屏幕显示激活码+本地播报数字音

    Device->>JavaAPI: POST /ota/activate (轮询, 202=继续)

    Note over Web: ===== 阶段 B: 用户绑定 =====

    Web->>JavaAPI: POST /device/{agentId}/bind/847291
    JavaAPI->>Redis: GET ota:activation:847291 → deviceId
    JavaAPI->>Redis: GET ota:device:{safeMac} → 校验
    JavaAPI->>JavaAPI: INSERT INTO ai_device
    JavaAPI->>Redis: DELETE 激活相关 key
    JavaAPI-->>Web: {code:0, msg:"success"}

    Note over Device: ===== 阶段 C: WebSocket =====

    Device->>Python: WebSocket CONNECT + hello
    Python->>JavaAPI: POST /config/agent-models
    JavaAPI-->>Python: {配置JSON} (设备已绑定)

    Note over Device: ===== 阶段 D: 正常对话 =====

    Device->>Python: {"type":"listen","state":"detect","text":"你好"}
```

### 5.3 两种部署模式差异

| 阶段 | 最简化部署 (read_config_from_api=false) | 全模块部署 (read_config_from_api=true) |
|------|---------------------------------------|---------------------------------------|
| OTA 端点 | xiaozhi-server Python (8003) | manager-api Java (8002) |

| "OTA 阶段校验绑定，未绑定返回假地址" | ❌ OTA 始终返回真实 WebSocket URL，未绑定与已绑定拿到的 WS 地址相同 |
| "未绑定设备返回无效固件地址来阻止升级" | ❌ 不准确。`firmware.url` 确实是 `INVALID_FIRMWARE_URL` 占位，但真正阻止升级的机制是：`firmware.version` 回显设备当前版本，设备 `IsNewVersionAvailable()` 做语义化版本比对发现相同，判定无更新，跳过 `Upgrade()` |
| "绑定提示只由 xiaozhi-server 播报" | ❌ 设备端 `ShowActivationCode()` 在 OTA 阶段本地播报一次；服务端在用户首次说话时通过 WS 再播报一次 |
| "没有 token 就播报绑定提示" | ❌ token 认证失败直接断开连接，不会播报 |
| "认证默认开启" | ❌ `auth.enabled` 默认 `false` |
| "连接建立时立即播报绑定提示" | ❌ 播报发生在用户说话时（`_route_message` → `check_bind_device`），不是连接建立时 |
