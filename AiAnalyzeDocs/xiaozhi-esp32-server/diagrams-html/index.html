设备连接与认证流程
ESP32 设备从 OTA 获取 WebSocket URL，携带 HMAC token 连接服务端，经历两道认证关卡（WebSocket认证 + 设备绑定校验）后进入正常通信。
WebSocket HMAC-SHA256 need_bind OTA
13
MQTT Gateway 服务交互
xiaozhi-mqtt-gateway 桥接 ESP32 与 xiaozhi-server：ESP32 通过 MQTT(:1883)传信令 + UDP(:8884)传音频 → Gateway 协议翻译 → WebSocket(:8000)转发到 server。服务端代码无需修改。
MQTT UDP 音频 协议桥接 OTA 凭证
10
连接关闭与资源清理
5种触发源（超时/断开/退出/超限/静默）触发关闭流程，守护线程并行保存记忆和标题，最后释放 TTS/ASR/VAD/WebSocket 资源。
超时检测 守护线程 资源释放

语音对话核心链路
从用户说话到 AI 回复的完整数据流
02
语音对话主流程
15步完整链路：音频bytes → VAD人声检测(Silero ONNX) → ASR流式识别 → startToChat → LLM对话 → TTS合成 → WebSocket音频发送。
VAD ASR LLM TTS 声纹识别
03
消息路由与文本消息分发
WebSocket 消息按类型分流：bytes→ASR队列，str→JSON解析→注册表查表分发到 7 种 Handler（hello/abort/listen/iot/mcp/server/ping）。
注册表模式 7种消息 JSON解析
04
LLM 对话与流式响应处理
chat() 方法完整链路：四段式消息组装(静态system+few-shot+动态system+历史) → OpenAI流式SSE → 逐chunk解析 → direct_answer/工具调用/纯文本三种路由。
流式SSE 前缀缓存 递归深度=5
05
TTS 语音合成与播放流水线
双线程生产者-消费者模型：文本队列→分段合成→音频队列→60ms间隔播放→WebSocket发送。支持 FIRST/MIDDLE/LAST 三段式状态机。
双线程 流控 预缓冲
T
意图与工具系统
智能路由与多协议工具调用
06
意图识别与工具调用链
三级预检（退出指令→唤醒词→模式分流）：function_call模式交给LLM自主决策，intent_llm模式独立分析。工具结果支持 RESPONSE/REQLLM/ERROR 三种动作。
function_call direct_answer 唤醒词
09
统一工具系统架构
UnifiedToolHandler + ToolManager 统一管理 5 类执行器：Server Plugin(天气/音乐/HA)、Server MCP(stdio/sse)、Device IoT(动态注册)、Device MCP(WS通道)、MCP Endpoint(外部服务)。
5类执行器 MCP协议 IoT
D
数据与记忆
对话记忆持久化与聊天数据上报
07
记忆系统: 加载与保存
连接时从 YAML/API 加载历史记忆注入 system prompt；对话中每轮查询记忆；关闭时守护线程调用 LLM"时空记忆编织者"生成结构化 JSON 持久化。
YAML存储 glm-4-flash 前缀缓存
08
聊天记录上报流程
ASR/TTS/工具调用三种数据源 → enqueue入队 → 守护线程消费 → opus转WAV → ManageApiClient POST上报到 manager-api（chatType: 1用户/2智能体/3工具）。
异步上报 opus→WAV 3种类型
O
运维与管理
固件升级与远程管理指令
11
OTA 固件升级流程
设备启动时 POST /xiaozhi/ota/ → OTAHandler解析model/version → 扫描 data/bin/ 目录版本比对 → 生成HMAC token → 返回 WebSocket URL + 固件下载地址。
HTTP接口 版本比对 HMAC token
12
管理指令处理（server消息）
manager-api 通过 WebSocket 发送 server 消息，经 secret 二次验证后分发指令：update_config（热更新组件配置）或 restart（子进程重启服务）。
双层密钥 热更新 子进程重启
