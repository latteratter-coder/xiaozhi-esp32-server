7种消息处理器详情

⑤ hello
客户端握手：交换 audio_params（音频格式）+ features（特性标志）。若支持 MCP 则初始化 MCPClient 并发送初始化消息。最后返回 welcome_msg。
⑥ abort
打断当前对话：设置 client_abort=True，清空 TTS/ASR 队列，发送 TTS stop 信号，重置说话状态。LLM 流式循环检测到此标志后自动终止。
⑦ listen
语音控制核心，3种 state：start（重置音频状态）→ stop（触发ASR识别）→ detect（直接使用文本，跳过ASR，支持唤醒词和 [device_call] 指令）。
⑧ iot
IoT设备管理：descriptors（设备能力描述符注册）+ states（设备状态上报）。异步处理，不阻塞主流程。
⑨ mcp
设备端 MCP 协议消息：将 payload 转发给 MCPClient 处理。支持 MCP 初始化、工具列表、工具调用结果等消息。
⑩ server
管理指令处理：先进行 secret 二次验证，再分发 action：update_config（热更新配置）/ restart（重启服务）。
⑪ ping
WebSocket 心跳保活：需启用 enable_websocket_ping。收到后更新活动时间戳，返回 {"type":"pong"} 响应。

流程说明

1
WebSocket 消息到达 _route_message()，首先按类型分流：str（文本JSON）vs bytes（音频帧）
2a
bytes 音频帧 → 直接放入 asr_audio_queue，由 ASR 线程消费处理
2b
str 文本 → 进入 handleTextMessage() → TextMessageProcessor
3
TextMessageProcessor.process_message() 对消息执行 json.loads() 解析，提取 type 字段
4
TextMessageHandlerRegistry.get_handler(type) 从注册表中查找对应的 Handler 实例（基于 TextMessageType 枚举值匹配）
5-11
7种 Handler 各自独立处理：hello(握手) / abort(打断) / listen(语音) / iot(设备) / mcp(协议) / server(管理) / ping(心跳)
!
JSON 解析失败 → 将原始消息回传给客户端
!
未知 type → 记录错误日志，不做任何处理
!
纯数字 int 消息 → 原样回传（兼容特殊客户端）
