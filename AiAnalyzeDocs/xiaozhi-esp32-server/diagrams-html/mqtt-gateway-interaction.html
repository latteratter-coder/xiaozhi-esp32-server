① 设备启动流程（OTA 下发 MQTT 凭证）

1
ESP32 上电，向 xiaozhi-server 发送 OTA POST 请求
POST http://server:8003/xiaozhi/ota/
2
xiaozhi-server OTAHandler 组装响应，从 server 配置读取 mqtt_gateway、mqtt_signature_key，生成 MQTT 凭证并返回
3
OTA 响应中包含 mqtt 字段：
mqtt.endpoint = "公网IP:1883"（MQTT Broker 地址）
mqtt.client_id = "GID_default@@@设备MAC@@@clientId"
mqtt.username = Base64({"ip":"unknown"})
mqtt.password = HMAC-SHA256签名（clientId|username, mqtt_signature_key）
mqtt.publish_topic = "device-server"
mqtt.subscribe_topic = "devices/p2p/设备MAC"
4
ESP32 连接 MQTT Broker（Gateway :1883），使用返回的凭证认证，订阅自己的 topic
5
ESP32 建立 UDP 通道（Gateway :8884），用于实时音频双向传输

④ 为什么用 MQTT 而不是 WebSocket 直连？

对比维度WebSocket 直连MQTT + UDP
断线重连慢（完整 HTTP 握手）快（持久会话，直接恢复）
NAT 穿透长连接易被路由器超时清除内置 Keepalive 心跳
音频延迟较高（TCP 拥塞控制 + 队头阻塞）低（UDP 直传，无拥塞）
功耗较高（TCP 开销大）较低（MQTT 协议轻量）
单机连接数~3 万/Python进程~50 万/MQTT Broker 节点
WiFi 休眠唤醒需重建连接唤醒后直接恢复会话
适合场景开发调试、局域网测试真实产品部署、百万设备
★
Gateway 的核心价值：对 ESP32 是 MQTT Broker + UDP 服务器，对 xiaozhi-server 是普通 WebSocket 客户端。服务端代码完全不用改，只需配置参数。
★
为什么要分 MQTT + UDP？ MQTT 传控制信令（"开始录音"、"停止"等小消息，需要可靠传输）；UDP 传音频流（Opus 编码大数据量，需要低延迟，允许丢包）。各司其职。
